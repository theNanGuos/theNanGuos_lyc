# WU-SUNO-002 本地候选保留策略

**Goal：** 让用户为单次生成选择本地保留 1、2 或全部候选，默认保留 1，同时保持供应商请求和费用语义不变。

**Architecture：** `retention_limit` 是本地任务字段，不进入 Kie/Suno payload。后端在成功终态校验完整候选后按供应商响应顺序截取，再下载并公开被保留候选。

**实际状态：** 见 [`STATUS.md`](../STATUS.md)。

## 2. 数据与行为合同

- 创建任务新增 `retention_limit: 1 | 2 | null`，默认 `1`，`null` 表示全部；其他整数或类型在 API 边界拒绝。
- 该字段只属于本次生成，不写入 `user_profile.json`，也不由自然语言或长期偏好推断。
- Kie/Suno 请求构造器不得增加“生成数量”字段；供应商实际生成数量与计费不受此值影响。
- `SUCCESS` 时先校验供应商所有完整候选，再按响应顺序保留前 N 个；下载 MP3、封面、结果 API 和作品索引只使用被保留候选。
- 协作日志记录 `provider_candidate_count`、`retention_limit`、`retained_candidate_count`，不得保存未保留候选的完整媒体 URL。
- UI 在 Suno 模型之后提供“本地保留：1 / 2 / 全部”，并明确提示不会减少供应商实际生成数量或费用。

## 3. 允许修改与非范围

允许修改核心 Schema、创建任务 API、生成/任务/存储服务、前端 API client、generation store、创作页及对应后端和前端测试；实施完成后同步 DATA_MODEL、API_SPEC、SPEC 和 UI 文档。

不改变供应商轮询状态、重试策略、回调 URL、模型枚举，不让前端上传路径，不删除未保留候选之外的任务产物，也不承诺用户可挑选“最佳”候选后再下载。

## 4. 实施顺序

1. 先增加 Schema/API 的合法值、默认值、非法值和序列化失败测试。
2. 增加生成链路测试，证明完整校验发生在截取之前，下载和公开结果只包含保留候选。
3. 增加日志安全测试，证明计数存在且未保留 URL 不落盘。
4. 实现后端字段传递、截取和日志；保持 Kie 请求快照不变。
5. 实现创作页单次设置和成本提示，补前端状态与 UI 测试。

## 5. 验证与完成标准

运行 Schema、API、生成链路、Suno 服务、日志安全、前端 store/UI、类型检查和构建测试。

完成标准：默认、1、2、全部及供应商返回不足 N 个均有确定性测试；未保留媒体不下载、不公开、不泄露 URL；Kie payload 与此前合同一致；实际候选数和保留数在日志可审计；验证证据只写入 `STATUS.md`。

## 6. 风险与回滚

默认保留 1 会丢弃用户可能更喜欢的后续变体，UI 必须在提交前说明。若供应商响应顺序不稳定，仍以该次响应顺序为唯一确定性规则，不引入主观评分。回滚时可恢复“全部保留”，但不得留下 Schema、日志和前端半兼容状态。
