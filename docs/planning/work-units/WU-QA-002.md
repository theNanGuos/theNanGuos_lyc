# WU-QA-002 M6 综合验收与文档对齐

**Goal：** 对 P10 的四个功能 WU 做完整的自动化、浏览器、视觉、安全和文档验收。

**Architecture：** 以设计事实源和正式产品/API/数据文档为合同，用 Mock 供应商完成稳定回归；供应商请求格式未变化，因此不以再次真实付费生成作为完成前提。

**实际状态：** 见 [`STATUS.md`](../STATUS.md)。

## 2. 验收范围

- 创作页：空输入、示例 placeholder、preview 清理、重试图标、焦点可见性、本地保留选择和成本提示；
- 等待页：全部步骤状态对齐、FIRST_SUCCESS 文案、无装饰性预计进度条；
- 候选保留：1、2、全部、不足 N 个、日志计数、未保留 URL/媒体隔离、Kie payload 不变；
- 播放：实际时间进度、pointer/keyboard seek、候选独立音量、结果页和全局播放器一致；
- 版本：作品页进入现有结果页，每个保留候选可选、可播、可下载；
- 删除：允许/禁止状态、确认文案、当前播放清理、404/409/文件失败、目录边界和无回收站；
- 回归：停止/继续、重启中断、偏好、知识、Range/下载、封面和五页其他既有能力。

## 3. 非范围

- 不在 QA WU 顺带增加新产品能力或重构共享架构；
- 不把 Mock 证据描述为真实 Kie 联调；如实现意外改变供应商 payload，必须退回 `WU-SUNO-002` 修正并重新决定是否需要付费联调；
- 不把截图差异直接改成新的导航、主要 CTA 或字段分组；实质偏离仍需用户确认。

## 4. 实施顺序

1. 对照四个 WU 的完成标准建立验收矩阵，补缺失的确定性测试。
2. 运行后端全量、前端单元、类型检查、生产构建和 Chromium E2E。
3. 在 1440×1024 重拍受影响页面和关键状态，逐项比较已确认基线；记录差异和用户确认结果。
4. 执行密钥/推理泄露、未保留 URL、删除路径、媒体定位和 Markdown 安全检查。
5. 同步 `PRD.md`、`SPEC.md`、`WEB_UI_DESIGN.md`、`DATA_MODEL.md`、`API_SPEC.md`、`ARCHITECTURE.md`；只在 `STATUS.md` 写当前状态和新鲜验证数量。
6. 运行文档合同、相对链接和 `git diff --check`，在本地 `PROGRESS.md` 记录问题、解决方式、防复发措施和提交状态。

## 5. 完成标准

M6 只有在以下条件全部满足时才能在 STATUS 标为 done：四个前置 WU 均具备产物与当前验证；全量自动化通过；主要浏览器流程可复现；受影响页面视觉与用户确认基线一致；可访问操作有名称和键盘路径；删除与候选隔离安全检查通过；正式文档与实现一致；未泄露密钥、推理、未保留 URL 或绝对路径。

## 6. 风险与交接

视觉测试可能因字体和媒体资源产生非功能差异，必须区分布局错误与环境噪声。真实供应商未来改变候选数量或顺序时，产品仍只承诺“按响应顺序最多保留 N 个”。交接必须列出新鲜命令输出、截图位置、未覆盖的人工检查和剩余风险，不得用预期测试数量替代实际证据。
